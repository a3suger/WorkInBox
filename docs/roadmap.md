# WorkInBox 開発ロードマップ

## 方針

WorkInBox は Thunderbird を置き換えるメールクライアントではなく、メールから発生する仕事を整理するための業務支援システムとする。

開発は機能単位ではなく、実際のメール運用フローが段階的に成立する順序で進める。

大きく以下の順序で構築する。

1. TrackingBox を完成させる
2. 待機状態を管理できるようにする
3. TriageBox により新着メールとの状態遷移を自動化する
4. ダッシュボードで全体状況を把握できるようにする
5. 実運用に耐える安定性・自動実行環境を整える

---

## v0.1 — メール追跡基盤【完了】

### 目的

Thunderbird で利用者がスターを付けたメールを WorkInBox の管理対象として継続追跡できる基盤を構築する。

### 主な機能

- IMAP 接続
- 指定期間内のスター付きメール探索
- SQLite へのメール情報保存
- 管理対象メールの継続追跡
- `WIB/Tracked` IMAP キーワードによる管理対象識別
- WorkInBox からのスター解除
- Thunderbird 側でのスター解除検出
- SQLite 消失時の管理対象復元
- 基本的な仕事一覧表示

### 到達状態

「Thunderbird でスターを付ける = WorkInBox で追跡を開始する」という基本動作が成立する。

---

## v0.2 — TrackingBox：作業分類 + FastAPI UI 基盤

### 目的

スター付きメールを「何をする必要があるメールか」に分類できるようにすると同時に、以後の WorkInBox 機能を操作するための Web UI 基盤を整備する。

### 作業タグ

- 締切あり
- スケジュール調整
- 回答必要
- 読む・検討

### 作業分類

- Thunderbird / IMAP タグの読み書き
- タグなしスター付きメールの抽出
- AI による作業タグ判定
- AI 判定結果の確認
- 利用者によるタグ修正
- 既に作業タグが付いているメールを再分類しない制御

### FastAPI UI

- FastAPI による Web アプリケーション基盤
- 管理対象メール一覧画面
- メールの基本情報表示
- 現在のタグ表示
- 作業タグの変更操作
- AI 分類結果の確認・修正操作
- 同期処理の実行と結果表示
- 今後の締切管理・待機管理・ダッシュボードを追加できる画面構成

### 到達状態

ブラウザから TrackingBox を利用でき、スター付きメールについて

- 現在の管理状態を確認できる
- 作業タグを確認・変更できる
- 未分類メールを AI で分類できる

状態とする。

ここで構築する FastAPI UI を、以後の WorkInBox の共通 UI 基盤とする。

---

## v0.3 — TrackingBox：締切管理

### 目的

メール本文から締切を抽出し、メールとは独立した締切情報として管理する。

### 主な機能

- 「締切あり」メールの抽出
- AI による締切日時候補の抽出
- 利用者による締切確認・修正
- 締切情報の SQLite 保存
- Active / Completed 状態管理
- 期限順表示
- 7日以内の締切抽出
- 今日の締切抽出

### 締切処理後の操作

- 回答処理：「回答必要」タグを付与
- 終了処理：「一括処理」タグを付与し、スターを解除

### 到達状態

WorkInBox で「いつまでに何を処理する必要があるか」を確認できる。

---

## v0.4 — TrackingBox：スケジュール調整支援

### 目的

スケジュール調整が必要なメールについて、支援者への依頼作業を簡単にする。

### 主な機能

- 「スケジュール調整」メールの抽出
- 「依頼済み」状態の管理
- 支援者への依頼メール生成支援
- 依頼完了後の「依頼済み」タグ付与

### 利用者が選択できる処理

- 依頼処理：支援者向け依頼メールを生成し、「依頼済み」タグを付与
- 自分で処理：「一括処理」タグを付与し、スターを解除
- 自分で確認して回答：「回答必要」タグを付与

### 到達状態

TrackingBox の主要機能が一通り成立する。

ここまでを TrackingBox MVP とする。

---

## v0.5 — 待機状態管理

### 目的

「自分が作業するメール」だけでなく、「相手の返信や対応を待っているメール」を WorkInBox で管理できるようにする。

### 主な機能

- 「返信待ち」タグ管理
- 「対応待ち」タグ管理
- 「依頼済み」履歴タグ管理
- 「一括処理」終了タグ管理
- 返信待ちメール一覧
- 対応待ちメール一覧
- 待機開始日時管理
- 7日以上経過した待機メールの抽出
- 催促対象の表示

### 到達状態

WorkInBox 上で、

- 自分がやる仕事
- 相手からの返信を待っている仕事
- 支援者の対応を待っている仕事

を区別できる。

---

## v0.6 — TriageBox：新着メール判定

### 目的

新着メールを分析し、TrackingBox の管理対象との関係を判定できるようにする。

### 対象

INBOX 内の未読メール。

TriageBox はメールを既読にしない。

### 主な機能

- 未読メール探索
- 広告・不要メール判定
- 自分が送信したメールの判定
- 返信メール判定
- `Message-ID` / `References` / `In-Reply-To` 等を利用した関連メール判定
- AI を利用した補助判定

### 到達状態

TriageBox が新着メールについて「これは何のメールか」を判定できる。

---

## v0.7 — TriageBox：メール状態遷移

### 目的

返信によって「現在注目すべきメール」が移動する WorkInBox のワークフローを自動化する。

### 主な機能

- 返信待ち案件への返信検出と状態遷移
- 対応待ち案件への返信検出と状態遷移
- 支援者依頼メールの検出
- 元メールのスター解除と「一括処理」付与
- 新しい注目メールへのスター・作業タグ付与

### 到達状態

メールのやり取りに応じて、現在注目すべきメールが自動的に更新される。

ここまでを Workflow MVP とする。

---

## v0.8 — ダッシュボード

### 目的

利用者が毎朝 WorkInBox を開くだけで、現在抱えている仕事の全体像を把握できるようにする。

### 主な表示項目

- 締切あり
- スケジュール調整
- 依頼済み
- 回答必要
- 読む・検討
- 返信待ち
- 7日以上経過した返信待ち
- 対応待ち
- 7日以上経過した対応待ち
- 一括処理の例外案件
- 7日以内の締切
- 今日の締切
- 今日の予定

### 主な機能

- 状態別件数表示
- 各項目から対象メール一覧へ遷移
- 締切一覧
- 待機期間表示
- 異常・例外状態の表示

### 到達状態

WorkInBox が「今日の仕事を始めるための画面」になる。

## v1.0 — 実運用版

### 到達目標

Thunderbird を通常通り利用しながら、WorkInBox を毎朝確認することで、

- 自分が対応する仕事
- 締切がある仕事
- スケジュール調整中の仕事
- 返信待ち
- 支援者対応待ち
- 今日注意すべき案件

を把握できる。

メールの閲覧・返信・送信・アーカイブは引き続き Thunderbird が担当する。

WorkInBox は「メールを読む場所」ではなく「メールから発生した仕事を整理する場所」として機能する。
