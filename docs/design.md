# WorkInBox 設計書

## 概要

WorkInBox は Thunderbird を補完するための業務支援システムである。

利用者のメール運用を大きく変えず、

- AI によるメール分類
- 締切登録支援
- スケジュール調整支援
- 待機案件整理

を提供する。

Thunderbird はメール処理と既存 UI を担当し、WorkInBox は仕事の整理を担当する。

WorkInBox は独立した TODO / プロジェクト管理アプリを目指さない。

---

## 設計原則

### 1. メールを入口とする

WorkInBox は既存メールから仕事を整理する。

メール以外から生じた仕事についても、自分宛て備忘メールを入口として利用できるようにする。

締切登録支援の途中では、対象メールから派生したマイルストーンを利用者が追加できる。

### 2. Thunderbird を置き換えない

メール閲覧、送信、返信、アーカイブ、タグ操作は Thunderbird を中心に行う。

WorkInBox は必要な整理画面と支援処理を提供する。

### 3. 正本を用途ごとに分ける

- メール本体: メールサーバ
- WorkInBox 作業タグ: IMAP keyword
- WorkInBox 内部状態: SQLite
- 正式締切: SQLite
- Thunderbird 向け締切表示: SQLite から生成する read-only `.ics` / VTODO

v0.2 では CalDAV を使わず、Thunderbird は `.ics` を読み取り専用で購読する。

### 4. AI は整理役である

AI は分類や抽出を支援する。

初期分類は重要な見逃しを減らすため再現率を重視し、最終的な修正・確定は利用者が行う。

---

## システム構成

### TrackingBox

スター付きメールを対象とする。

主な機能:

- AI 初期分類
- 判定保留 UI
- 締切登録支援
- スケジュール調整支援
- 特殊処理後の次作業提案

### TriageBox

未読メールを対象とする。

主な機能:

- 広告・不要メール判定
- 自分発メールの役割判定
- 返信メール判定
- 返信待ち / 対応待ちの追跡

TriageBox はメールを既読にしない。

## 主なタグ

### 参照

- `重要`

### 作業

- `締切あり`
- `スケジュール調整`
- `回答必要`
- `読む・検討`

### 判定状態

- `判定保留`

### 完了

- `締切登録済み`
- `スケジュール対応済み`

### 待機・履歴・終了

- `返信待ち`
- `対応待ち`
- `依頼済み`
- `一括処理`

## 締切登録支援

`締切あり` メールについて AI が 0〜複数の締切候補を抽出する。

各候補を利用者が、

- 登録しない
- 修正する
- 登録する

から処理する。

AI が日付を抽出できない候補は日付未確定として残し、利用者が補完できるようにする。

利用者は対象メールを起点として新しい締切を追加できる。

正式登録された締切は SQLite が正本である。

全候補の判断が完了し 1 件以上正式登録された場合に `締切登録済み` を自動付与する。

SQLite の正式締切から read-only `.ics` / VTODO を生成し、Thunderbird で購読する。

v0.2 では締切とメールの関連を Message-ID 単位で保持する。

スレッド / 案件単位の Context と関連締切一覧は後続バージョンで検討する。

---

## Thunderbird の役割

Thunderbird は以下を担当する。

- メール閲覧
- メール送信
- 返信
- アーカイブ
- WorkInBox IMAP タグの確認・修正
- WorkInBox が生成した read-only ICS / VTODO の閲覧

WorkInBox 由来の締切の追加・修正・削除は v0.2 では WorkInBox 側で行う。

---

## TODO アプリ化しない境界

WorkInBox は、メールから仕事を発見し、締切等の構造化情報へ変換するところまでを担当する。

一方、次のような一般的なプロジェクト管理機能は原則として持たない。

- カンバン
- 進捗率
- プロジェクト階層
- 全タスクの汎用手入力 UI

将来 Thunderbird から締切を編集・完了し、その結果を WorkInBox に戻す必要が明確になった場合は CalDAV 等を検討する。
