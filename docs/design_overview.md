# WorkInBox 全体設計

## 概要

WorkInBox は Thunderbird を補完する業務支援システムである。

Thunderbird はメール本文の作成・送信・返信・アーカイブ等のメール実行環境、WorkInBox はメールから発生する仕事・判断・待機・参照情報を整理する環境とする。

WorkInBox は独立した TODO / プロジェクト管理アプリや独自メールクライアントを目指さない。

主な対象は次のとおり。

- AI によるメール分類
- 締切登録支援
- スケジュール調整支援
- 返信待ち・対応待ちの整理
- `見る・検討` から作成する Record
- Thunderbird との業務フロー連携

正式な状態遷移・タグ・業務フローは `docs/design.md` を正とする。

---

## 設計原則

### 1. メールを入口とする

WorkInBox は既存メールから仕事を整理する。

どの未着眼メールに新たに着眼するかは利用者が決め、スターで表す。

TriageBox は既存の利用者判断を relation に基づいて引き継ぐ場合だけ、新着メールへ着眼点を移すことができる。

### 2. WIB を仕事の出発点にする

利用者は原則として WIB ダッシュボードから仕事を始める。

- 着眼判断が必要なメールを把握する。
- Thunderbird で必要なメールへスターを付ける。
- TrackingBox / TriageBox が整理する。
- WIB で業務全体を確認し、仕事の種類に応じて WIB または Thunderbird へ進む。

### 3. Thunderbird を置き換えない

通常ワークフロー (`返信必要` / `見る・検討` / `注目`) のメール閲覧・処理は Thunderbird で行う。

専用ワークフロー (`締切あり` / `スケジュール調整`) は WIB で進める。専用ワークフローに属するメールの閲覧は WIB を起点とし、本文作成・送信そのものは Thunderbird の機能を利用する。

WIB は独自の送信エンジンを持たない。

### 4. 正本を用途ごとに分ける

- メール本体: メールサーバ
- WorkInBox 作業タグ: IMAP keyword
- WorkInBox 内部状態・relation・専用ワークフロー状態・Record: SQLite
- 正式締切: SQLite
- Thunderbird 向け締切表示: SQLite から生成する read-only `.ics` / VTODO

### 5. AI は整理役であり、利用者が修正できる

AI は分類、抽出、要約、優先順位付けを支援する。

AI 判定は IMAP タグ等へ反映できるが、利用者は結果を修正できる。

専用ワークフロー候補は見逃しコストを考慮して独立判定し、通常フローは `返信必要` / `見る・検討` / `注目` / `何もしなくてよい` から判定する。

## システム構成

```text
WIB Web UI + Thunderbird Extension
  = 利用者判断・ワークフロー進行・待機案件対応・Record管理・Thunderbirdとの接続

TrackingBox
  = 意味・分類・要約・優先順位・再評価

TriageBox
  = 事実・関係・決定的な状態遷移
```

### WIB Web UI + Thunderbird Extension

- ダッシュボードを仕事の出発点として提供する。
- 専用ワークフローを進める。
- `判定保留` を利用者が確定する。
- `返信待ち` や Record を管理する。
- Thunderbird のメール作成・送信・表示・Quick Filter と接続する。

### TrackingBox

スター付きメールを対象とし、本文の意味を AI で整理する。

- AI 初期判定
- TriageBox 後の再判定
- 締切候補抽出
- スケジュール調整支援
- `返信待ち` の要否・優先順位・再評価
- Record の AI 要約

### TriageBox

INBOX の未読メールを対象とし、TrackingBox より先に動作する。

- 自分発メールの検出
- `In-Reply-To` / `References` / WorkInBox relation の解析
- `返信待ち` / `対応待ち` への返信検出
- relation に基づく着眼点移動
- 専用ワークフロー relation の保存
- 決定的処理後のスターなし新着に対する広告等の補助 AI 判定

TriageBox はメールを既読にしない。

## 主なタグ

### 参照

- `重要`

### 専用ワークフロー

- `締切あり`
- `スケジュール調整`

### 通常ワークフロー

- `返信必要`
- `見る・検討`
- `注目`

### 判定状態

- `判定保留`

### 専用ワークフロー完了

- `締切登録済み`
- `スケジュール対応済み`

### 待機・専用ワークフロー状態

- `返信待ち`
- `対応待ち`
- `対応あり`

### 履歴・整理

- `依頼済み`
- `一括処理`

タグの意味、排他・共存関係、終了方法、表示名と IMAP keyword の対応は `docs/design.md` を参照する。

## 専用ワークフロー

専用ワークフローを進める主体は WIB とする。

利用者が次のいずれかを行うまで終了していない。

1. 完了させる
2. 非該当として解除する

スケジュール調整等で支援者へ新規メールを作る場合、標準 Reply では表せない起点 M1 と新規メール M2 の関係を `X-WorkInBox-Origin-Message-ID` と SQLite relation で保持する。

専用ワークフローの起点メールと、起点メールの標準スレッド上で現在着眼しているメールは分けて管理する。

---

## 通常ワークフロー

通常ワークフローは Thunderbird で処理する。

利用者が通常ワークフローを終了する場合は、元の通常ワークフロータグを残し、`一括処理` を付けてスターを外す。

`見る・検討` を Record として保存する場合は別経路とし、`一括処理` を付けず、`見る・検討` を残したままスターを外す。

---

## Record

Record は `見る・検討` のメールから、後で参照・検索・再利用する価値がある情報を WIB に残す仕組みである。

メール本体を複製せず、Message-ID で元メールを参照する。

最低限、タイトル、AI 要約、利用者メモ、元メール参照を持つ。

---

## TODO アプリ化しない境界

WorkInBox はメールから仕事を発見・整理し、必要なワークフローや構造化情報へつなげるところまでを担当する。

一般的なプロジェクト管理機能は原則として持たない。

- カンバン
- 進捗率
- プロジェクト階層
- 全タスクの汎用手入力 UI
